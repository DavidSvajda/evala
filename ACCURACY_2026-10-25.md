# Game accuracy — Evala 2.2.3

The previous game percentage was an arithmetic mean of stored move scores. Routine
moves could dilute a decisive error. Game summaries now compute directly from all
stored White-POV position evaluations, including the actual initial position. Existing
saved reviews update on load without another engine search.

The metric follows the public Lichess model as inspected on 2026-10-25:

- Clamp centipawns to ±1000; convert mate scores to the corresponding bound.
- Convert evaluations to winning chances using the published logistic coefficient.
- Score each move's lost winning chances with the exponential accuracy curve,
  including the current implementation's one-point uncertainty adjustment.
- Use population standard deviation in sliding windows of 2–8 positions as weights,
  bounded to 0.5–12. Combine the weighted mean with the harmonic mean; harmonic
  denominators use a floor of 1, matching the public implementation.
- Respect the actual mover, including Black-to-move imported positions.

Only complete reviews with every required score receive a whole-game percentage.
Nonterminal positions below depth 12 mark the percentage as provisional. This depth
label is Evala's presentation policy, not a claim that depth 12 ensures accuracy.
Short or already decided games remain less informative. Engine version, settings
and analysis depth influence scores; no conversion to a rating or exact Chess.com
CAPS2 equivalence is claimed. Per-phase statistics retain their explicitly labelled
move averages, and the separate uncalibrated performance estimate is unchanged.

Scoped validation: seven accuracy/performance unit checks, one browser check of
saved-game recomputation and Czech/English presentation, plus the existing minimal
container smoke before publishing. No broad browser suite or full unit suite was
requested or run for this release. The workflow's default remains full validation;
the explicit `accuracy` dispatch profile selects only these scoped checks.
